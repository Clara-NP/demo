# ADR 使用说明与索引

> 本文件是 `docs/adr/` 目录的**元规则 + 索引**：说明什么该写进来、怎么写、怎么维护。
> 它本身不是一条 ADR，不占编号。

---

## 0. 结论

| 项 | 规定 |
|---|---|
| 放什么 | **做过的高成本技术选择**：影响多模块/长期演进、有过多个合理备选、推翻代价高 |
| 不放什么 | 需求、详细设计、编码细则、操作步骤、Bug 分析、进度 |
| 一篇写多少 | 一个决策，1~2 页 |
| 已接受的 ADR | **不修改**；要改就新写一篇并标 `Supersedes` |
| 编号 | 四位连续，从 `0001` 起，不复用、不回收 |

**唯一不可替代的价值**：记录“**为什么没选另一条路**”。设计文档只写怎么做，不写这个。

---

## 1. 判定标准（三问全“是”才写）

| # | 问题 |
|---|---|
| 1 | 这个选择会影响多个模块或长期演进吗？ |
| 2 | 当时是否存在多个都说得通的备选？ |
| 3 | 半年后想推翻它，代价高吗？ |

只满足一条的，通常该归到 `docs/standards/`（规则）或 `projects/<id>/docs/design/`（方案）。

---

## 2. 该放 / 不该放

### 2.1 平台级 `docs/adr/`（影响所有工程）

| 编号 | 标题 | 为什么是 ADR |
|---|---|---|
| 0001 | 板级配置：分层头文件 + 逻辑 ID，还是 DTS | 三方案并存，迁移成本高 |
| 0002 | 为何禁止动态内存，改用静态池 | 影响所有模块 |
| 0003 | 构建为何选 CMake + Presets，而非 Keil / Zephyr | 工具链锁定 |
| 0004 | HAL 为何用 ops 函数表，而非直接包 SDK | 决定移植成本上限 |
| 0005 | `libs` 依赖管理：默认单份共享，不引入 submodule | 影响协作方式 |
| 0006 | 为何要求 commit 关联方案文档章节 | 影响全仓历史 |
| 0007 | 为何 host 单测优先，HIL 只做验收 | 决定“什么算完成” |
| 0008 | 为何禁止业务层 `#ifdef` 区分芯片 | 抽象边界 |

### 2.2 工程级 `projects/<id>/docs/adr/`（只影响该工程）

| 例子 | 说明 |
|---|---|
| 为何选 SPI 而非 I2C 接该传感器 | 涉及具体器件与时序 |
| 控制周期为何定 1 kHz | 涉及具体硬件性能 |
| bootloader 分区为何 16 KB | 涉及具体 Flash 布局 |

**判定**：提到具体芯片 / 引脚 / 时序 → 工程级；否则平台级。

### 2.3 不该放的

| 内容 | 正确归属 |
|---|---|
| 需求、用户故事 | issue / `projects/<id>/docs/design/<task>.md` |
| 某功能的接口、时序、数据流 | `projects/<id>/docs/design/` |
| 编码风格细则（缩进、命名） | `docs/standards/coding-style.md` |
| 操作步骤（加工程、升级环境） | `docs/guides/` |
| Bug 分析与修复过程 | commit + issue |
| 进度、待办 | `TODO.md` / issue |
| 未形成技术决策的会议结论 | 不记录 |

## 3. 模板

新建文件时复制以下结构，命名 `docs/adr/NNNN-<kebab-title>.md`：

```markdown
# ADR-NNNN <一句话标题>

- 状态：Proposed        # Proposed / Accepted / Superseded / Deprecated
- 日期：YYYY-MM-DD
- 取代：无 / Supersedes ADR-00xx

## 0. 结论
3 行内：选了什么、代价是什么。

## 1. 背景
现象 + 约束（为什么要做这个决定）。

## 2. 备选方案
| 方案 | 优点 | 缺点 | 结论 |

## 3. 决策
选哪个，一句话。

## 4. 后果
- 正面：
- 代价 / 缓解：
- 不这么做的后果：
```

**超过 2 页说明在写设计文档，不是决策记录。**

---

## 4. 状态机

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `Proposed` | 已提出，未定 | 讨论后可改内容 |
| `Accepted` | 已生效 | **内容冻结**，只允许改状态字段 |
| `Superseded` | 被新 ADR 取代 | 头部加 `Superseded by ADR-00xx` |
| `Deprecated` | 不再适用且无替代 | 头部注明原因 |

**已接受的 ADR 不修改正文**——修改会抹掉历史，让后人无法理解“当时为什么这么想”。

---

## 5. 在环境中的作用

| 作用 | 表现 |
|---|---|
| 给 AI 的硬约束 | AI 想“顺手重构”前先读到理由，不会重复走死路 |
| 防止重复讨论 | 同一问题半年后被重提，直接给链接 |
| 降低接手成本 | 新人与新智能体无需考古 commit 历史 |
| 记录放弃的路径 | 唯一能回答“为什么不用 DTS / 不用 submodule”的地方 |
| 变更可追溯 | 决策链通过 `Supersedes` 串联 |
